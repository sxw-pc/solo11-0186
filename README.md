# 塔机吊装作业采证台

吊物方案、塔机索具人员和现场起落钩三账联动，决定起吊放行、停工、悬吊处置及完工。所有数据均为虚构离线样例，金额无涉；载荷使用千克，长度使用米，风速使用米/秒。本项目不控制真实设备。

Python 3.11+ / SQLite，合成数据离线运行。

```powershell
python -m pip install . --no-deps --no-build-isolation
python -m liftpermit demo --db demo.sqlite
python -m liftpermit report --db demo.sqlite
python -m liftpermit audit --db demo.sqlite
python -m unittest discover -s tests -v
```

独立入口：plan-import、asset-import、work-import、sling-capture-import。每项导入格式为 `--db state.sqlite --file fixtures/<name>.json`。同源重复幂等，异内容复用事件 ID 则整批回滚。`audit` 在空库重放原始文件并比对业务状态。

## 三套业务账与证据

- `plan-import` 从吊物估重与独立复测选当前重量，按方案版本计算重量乘半径的力矩；吊点支撑线/多边形须覆盖重心。回转路径线段与有效禁入区矩形相交则必须重画，旧签认不能跟随新版。持久化吊物测量、吊点方案和禁区公告。
- `asset-import` 用当前半径、臂长查塔机额定曲线并施加动态载荷系数；每根索具按角度折减后的能力、吊点数及有效检验期单独核对。指挥员资质与连续班次须覆盖作业窗，同塔机重叠预留会冻结许可。持久化塔机检验、索具证书、人员排班和预留。
- `work-import` 对有校准凭据的双源连续风速作停工与复工判定。离地未落钩遇资源故障或停工时，按吊物重量、回转半径、禁区和可用期选择应急落点；没有安全落点会单独报告。挂钩、离地、落钩、独立监理签收须按时间顺序完成，且事件晚于当前方案许可和复工授权。持久化作业许可、风速观测、应急落点和起落钩事件。

三个入口可在缺少其它账时独立采录并给出待核状态。完整演示依次导入正常、失败、恢复各三份 fixture，观察复测超载、索具报废/故障、双源超风速如何改变现场结果，再由新版方案、新资源和有效复工令恢复。`decision_history` 保留每次导入后的旧裁定；`audit` 从留存的原始字节在空库重算并与当前业务表比较。`demo` 报告打印 `imported_module`，用于确认导入的是本仓源码。

## 三吊点索具负荷分担

“重心落在吊点多边形内”只保证静力可支撑，不代表三根索具平均受力。合成 J7 用三吊点 (-1,0)、(1,0)、(0,1) 与重心 (0.8,0.1)：旧 `plans._center_supported` 判真、旧等份阈值 1800×1.1÷3 = 660 kg 也过关，但刚性静力的三角形重心权重为 (0.05, 0.85, 0.10)，靠近第二吊点的索具垂直动态负荷约 1683 kg，超过单根 1000 kg/30° 折减后的 866 kg。因此 `resources` 不再用“总张力或平均值”给索具组合下结论。

- `sling-capture-import` 接收签章的拉力计批次：每只仪表的设备 UID、绑定索具 RFID、采样时刻、校准曲线、量程、零点、原始牛顿值与离地阶段标签都逐条落入 `capture_batch` / `capture_reading`，可离线复核。`tension_capture.loadshare` 用每只仪表自己的曲线换算 kgf，只在同一 `off_ground` 阶段、按批次时钟容差配对，逐根除以该索具的角度折减能力得到实测利用率。
- 无法配对、超量程、吊点与索具错绑、同一 RFID 被两只仪表认领、零点重置或批次内曲线被改动、离地前试拉与离地后摆动峰值，都会作为独立标记报告；试拉/摆动峰值只记录、不参与离地判定。缺失的一根标为 `unpaired`，绝不按总根数补平均。
- 每个 job 同时给出三种不同来源：`measured`（逐根同步实测）、`equal_division`（旧的质量×1.1÷根数）、`geometry`（签章坐标的重心静力包络）。`sling_ok` 只在某一来源真正证明每根合格时为真；无传感器证据的旧 JSON 仍按等份解释。
- 批次绑定其采集时的方案几何摘要（吊点、重心、RFID 绑定的哈希）、方案版本与资源版本。新方案改变吊点或重心、或资源改装后 RFID 绑定变化时，旧测量被标为 `stale` / `misbound`，不得倒填为新方案的放行证据；历史超载仍留在 `capture_batch` 供追溯。离地未落钩而当前方案的实测超载被接受时，`work` 进入应急落地。

两条合法取证路线起点相同（J7 重心、1800 kg、旧三索具）：

1. **保守停工**：只用签章吊点坐标与刚性静力模型，第二根上界 ≥1683 kg，停止并重新布索（无需第三只拉力计）。
2. **均载梁改装**：装检验合格的均载梁，用两端经校准拉力计与梁的分配证书证明三索具各 ≤800 kg，更新资产版本与方案签认后放行。若梁证书只覆盖静载、不覆盖离地摆动，仍判 `pending_off_ground_certificate` 待核。

`fixtures/sling-imbalance.json` 为 J7 的离地批次（实测 90/1530/180 kgf，第二根超载）；`fixtures/asset-j7-beam.json` 与 `asset-j7-beam-static.json` 分别为覆盖/不覆盖离地摆动的均载梁证书。`tests/test_sling_loadshare.py` 量化三角形反例、错绑与缺帧、试拉峰值排除、两条取证路线、改装前后版本关系与回归。

源码和测试仍显著小于提示词建议的 2500–4500 行；已对八项首版能力、十二项决定和三条跨账路径逐一写业务测试，但这不保证未来每仓可稳定产出十条困难题。正常和失败样例均为合成数据，未与真实安全规程或实际设备联调。
